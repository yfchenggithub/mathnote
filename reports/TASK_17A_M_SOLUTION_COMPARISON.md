# Task 17A-M：模块化发布方案比较

状态：**PROPOSED**；2026-10-14。基线是 [`publish.py build-content`](../scripts/zhishu/publish.py#L87) 的完整 v2 包；三种方案均须另立模块包 schema/跨包引用契约，不能以过滤数组代替完整校验。

| 维度 | A：完整包后切片 | B：Publisher 原生模块选择 | C：重建管线 |
| --- | --- | --- | --- |
| 现有代码改动 | 小；新增独立 slicer/校验器，原 CLI 不变 | 中；发现、映射、包构建、CLI 与校验均需分支 | 大；重写或迁移多个模块 |
| 数学准确性 | 直接复用正式全集 DTO 与资源字节，差异可逐实体比较；源内容正确性仍由原流程负责 | 若只读子集，易遗漏全集关系或改变结构顺序 | 双管线并行时最难证明一致 |
| 数据一致性 | 需复制原节点、搜索和资产记录，重算模块 Manifest | 需防止子集重建改动 `sortOrder`、结构 ID | 迁移与双写风险高 |
| 资源完整性 | 可按全集注册 URI 精确复制、哈希核验 | 需重新集成图片预处理、PDF/MP4 登记 | 需重新建立全部资源规则 |
| 跨模块关系 | 18 条现有边界关系需额外外部引用文件及安装端解析 | 同样需要；提前过滤会使目标“未知” | 同样需要，无法靠重构消除 |
| 发布速度 | 每次先全量图片预处理和完整包，切片快；首段慢 | 可以只构建目标模块，但需重做全局关系索引 | 不可预测，早期最慢 |
| 全集兼容性 | 最强；不触碰原命令或 v2 输出 | 需严格维持无参数默认路径 | 最大回归面 |
| 跨学科能力 | 模块 schema 可先学科中立；源发现日后扩展 | 当前固定 11 个数学源目录和数学根，抽象量较大 | 可从头抽象，但成本最高 |
| 长期维护 | 额外一个切片器和模块校验；应避免重复映射逻辑 | 单管线但更多条件分支 | 新旧并存期成本最高 |

**推荐 A**，以正式完整 v2 包为唯一事实来源，切片器复制记录和资源，独立输出模块包。前提是能只读访问并验证一个完整 v2 包；本次环境对既有 `build/zhishu-content-package` 读取被拒绝，故**未实证跑通 A**。后续若产包成本成为瓶颈，再基于已冻结的模块 schema 评估 B 的增量构建，不能先牺牲全集语义换速度。C 当前缺乏必要性。

模块选择位置的三种具体放法：

1. **读取阶段**：读取少量源，速度潜力最高，却不知道被排除 UID 的 `related_ids` 目标是否有效，也可能改变全局 `sortOrder`；与现行 [`_build_relations`](../scripts/zhishu/runtime_mapping.py#L308) 的全集存在性语义冲突。
2. **正式内容构建阶段**：在 DTO 生成后、打包前过滤，可读取全集关系，但现行 [`validate_package`](../scripts/zhishu/content_package.py#L489) 的根/端点/资源约束仍需模块分支。CLI 和流水线改动较大。
3. **完整正式包后处理**：继承已验证的 DTO、图片转换与哈希，最容易实现实体字节一致性；代价是先全量构建。建议作为第一阶段。只读切片输入、独立模块输出，不覆盖 `build/zhishu-content-package`。

## 全集兼容与回归建议

保留 `build-content` 无参数的输出目录、schema v2、五个 JSON 文件、资源 URI、计数和排序规则；新模块入口采用单独命令/脚本和独立输出根，初期不要求修改 `publish.py`。已存在的 [`tests/test_zhishu_publish.py`](../tests/test_zhishu_publish.py#L32) 验证默认参数和调用；[`tests/test_zhishu_content_package.py`](../tests/test_zhishu_content_package.py#L128) 验证包字节确定性、URI、校验与差分。本次执行两文件共 **30 项测试，全部通过**。

后续实施时新增的关键回归：同一输入重复构建全集 v2 字节与 Manifest 对照；旧完整包和新完整包的节点 ID/`sortOrder`/搜索/资源 URI/哈希差异应为零；集合与解析几何包中的每条共享实体同全集一致；删除/篡改任一资源、跨包关系和 Manifest 字段应失败；视频删除保护、无视频 v2、旧 v1 隔离迁移测试继续通过；模块 V1→V1.1 的变更仅影响预期 UID/哈希/版本。上述为测试建议，**本次未执行**模块包回归或 Android 安装测试。

## 五个风险优先级

1. 现有 v2 校验不容许跨包悬空端点；新契约必须定义外部边，并经 Zhishu 验证。
2. 一级分类与源目录不一一对应，按目录筛选会错包。
3. 原节点顺序在全集上下文生成，子集重算会改变显示顺序。
4. 正式 MP4 由独立 `animation-shares.json` 登记，不能只过滤图片资源。
5. 完整包目前不可读，模块切片的端到端可行性仍是 PENDING。
