# Zhishu Math Motion Design System v1.0

## 知树数学 GIF · Apple-Inspired Visual Guidelines

**适用项目：** MathNote / 知树

**适用范围：** 所有新增及后续视觉精修的数学 GIF

**文件位置：** `scripts/manim/VISUAL_GUIDELINES.md`

**参考作品：** T021 Task 14C.2B 精修版

**基础设施：** Task 13F FINAL FREEZE

**规范状态：** v1.0 已集成候选规范；跨知识类型及 Android 真机验证仍待完成，尚未最终冻结。

---

## 1. 核心设计哲学

### 1.1 Mathematics First — 数学第一

数学 GIF 首先是一种教学内容，而不是视觉装饰。

数学准确性永远高于视觉美观。

不允许为了美观而改变：

- 数学坐标与比例。
- 函数曲线的真实形状。
- 几何点和线的位置关系。
- 运动轨迹。
- 数学变换顺序。
- 关键参数及条件。
- 公式与图形的对应关系。

**数学对象决定如何运动，视觉设计决定如何让运动被看懂。**

### 1.2 Clarity — 清晰

每个画面必须明确回答：

**当前最希望学生看到什么？**

一个画面只设置一个主要教学焦点。

其他信息应当降低视觉权重，或者在需要时再出现。

### 1.3 Deference — 内容优先

数学图形应该比装饰性容器更突出。

尽量避免：

- 厚重的矩形边框。
- 多层嵌套卡片。
- 大面积渐变背景。
- 装饰性阴影。
- 过度使用图标。
- 过多同时强调的颜色。

视觉设计应该帮助理解数学，而不是吸引学生去关注界面本身。

### 1.4 Meaningful Motion — 有意义的运动

所有主要动画必须服务于数学理解。

优先展示：

- 变化。
- 对应。
- 比较。
- 极值。
- 边界。
- 不变量。
- 转化。
- 数学关系的形成。

禁止使用与数学内容无关的炫技动效。

### 1.5 Progressive Disclosure — 渐进展示

不要一开始就展示所有公式、文字和推导。

推荐：

**建立问题 → 发生变化 → 发现规律 → 得出结论。**

每一步只提供当前需要的信息。

## 2. 信息层级规范

一张数学 GIF 只能有一个第一视觉焦点。

视觉优先级固定为：

**P1：核心数学图形或数学过程。**

**P2：当前操作或关键数学结论。**

**P3：参数、辅助说明、图例与坐标刻度。**

任何辅助元素都不应持续抢夺 P1 的视觉注意力。

### 2.1 标题规范

标题要求：

- 简洁。
- 数学准确。
- 能帮助学生识别当前知识主题。
- 尽量控制在一行。
- 不重复显示完整知识目录。

推荐标题风格：

- 顺序不同，结果相同
- 最值点为什么换位？
- 切线如何变化？
- 为什么距离会变成零？
- 两个事件为什么不独立？

完整知识标题仍保留在知树知识详情页。

GIF 标题不需要重复所有正式名称与条件。

### 2.2 当前操作

当前操作可以采用：

- 横坐标 ×1/2
- 对称轴经过中点
- 两条曲线完全重合
- 关于 x 轴翻折
- 切线与曲线相切

应当短、准确、明显。

### 2.3 辅助解释

每个阶段尽量只保留一句必要解释。

例如：

**P 在 y 轴上，因此横向压缩时位置不变。**

不要同时在画面中重复显示相同含义的公式、长句和步骤列表。

## 3. 画面比例与空间布局

### 3.1 默认画布

推荐：

- 方向：竖屏。
- 比例：9:16。
- 参考分辨率：576×1024。
- 背景：浅色。
- 内容避让边距：左右约 28～40 像素。

以上是设计基准，不是所有动画必须采用的固定画布。

### 3.2 空间比例

对于具有主要数学图像的 GIF，建议：

| 区域 | 推荐占比 |
|---|---|
| 标题与状态 | 10%～16% |
| 核心数学图形 | 50%～65% |
| 当前操作与结论 | 20%～30% |
| 剩余空间 | 自然留白 |

这些比例允许根据数学内容调整。

例如：

- 函数变化：优先扩大函数图像。
- 几何构造：优先扩大几何图形。
- 概率实验：优先展示样本变化。
- 代数推导：允许主要区域展示公式变化。
- 立体几何：允许为三维结构保留更多空间。

**统一设计原则，不强制统一页面模板。**

### 3.3 留白

留白应有明确作用：

- 分隔不同信息层级。
- 避免曲线与文字相互干扰。
- 让数学对象更容易辨认。

不应为了填满画面而增加无关文字。

但也不能因为装饰性留白过多，导致数学图形在手机上过小。

## 4. 字体与数学排版规范

### 4.1 字体原则

参考苹果产品的字体层级与阅读体验。

采用：

- 清晰的无衬线中文字体。
- 稳定的数学公式字体。
- 一致的标题、正文与说明层级。

不要求使用苹果专有字体。

优先复用现有 Manim 环境已验证的字体。

### 4.2 建议字体层级

以最终输出 576px 宽的 GIF 为参考，以下为渲染后实际像素高度的初始建议，而非 Manim 的 `font_size` 参数。

| 层级 | 建议显示高度 | 字重 |
|---|---|---|
| 主标题 | 30～38 px | Semibold |
| 当前操作 | 27～34 px | Medium / Semibold |
| 关键数学公式 | 28～40 px | 按公式结构 |
| 辅助说明 | 24～29 px | Regular / Medium |
| 必要坐标标签 | 20～26 px | Regular |

必须根据 GIF 在知树 App 中的实际显示宽度检查文字可读性。

长公式可以适当缩小，但应优先通过分行、拆分或减少重复内容解决，而不是无限缩小字号。

### 4.3 字体使用限制

同一 GIF 尽量只使用：

- 一套中文正文体系。
- 一套规范数学公式体系。
- 不超过三个主要文字层级。

避免同一画面出现五六种字重和字号。

### 4.4 数学公式准确性

必须检查：

- 分数。
- 根号。
- 上下标。
- 希腊字母。
- 正负号。
- 等号。
- 不等号。
- 括号。
- 适用条件。

数学公式不得因视觉适配被改写为不等价形式。

## 5. 颜色系统

### 5.1 推荐设计色板

以下为建议色值，可在视觉测试后微调，并非从 T021 GIF 精确反向提取的颜色。

| 角色 | 建议颜色 | HEX |
|---|---|---|
| 背景 | 极浅灰白 | #F7F8FA |
| 主文字 | 深蓝黑 | #213044 |
| 次要文字 | 蓝灰色 | #526275 |
| 基准数学对象 | 蓝色 | #2778BD |
| 第一动态对象 | 橙色 | #CD6031 |
| 第二动态对象 | 紫色 | #8055B2 |
| 关键追踪点 | 金色 | #B77D12 |
| 最终结果强调 | 绿色 | #158068 |
| 坐标轴 / 辅助线 | 浅蓝灰 | #A7B4C2 |

### 5.2 颜色语义

优先建立稳定的数学对象颜色角色。

例如 T021：

- 蓝：原始正弦函数。
- 橙：路径一。
- 紫：路径二。
- 金：追踪点 P。
- 绿：共同结果或最终函数。

其他 UID 可以根据实际数学对象调整。

例如圆锥曲线的红色圆周，或函数最值的红色最大值点，不必为了统一而强行改成橙色。

**跨 UID 统一的是角色清楚、同一对象颜色连续一致，而不是每个颜色必须代表同一种数学概念。**

### 5.3 控制强调色数量

同一时刻建议不超过 2～3 种强强调色。

未被关注的对象可以降低饱和度或透明度。

但不能让重要的数学对象因颜色过淡而难以辨认。

### 5.4 可读性要求

重要文字应尽量达到 4.5:1 的对比度目标；关键图形线条应尽量达到 3:1 的非文字对比度目标。

辅助网格和非关键信息可适当更淡。

颜色不能是区分两种数学对象的唯一依据；必要时配合线型、标签或点标记。

## 6. 数学绘图规范

### 6.1 图形必须准确

严禁：

- 不经过切点的切线。
- 假交点。
- 错误的垂线。
- 位置不准确的焦点。
- 错误的运动轨迹。
- 为视觉效果改变几何比例。
- 图形与实时公式不一致。

### 6.2 坐标系

保留教学必要的坐标信息。

优先保留：

- 关键坐标轴。
- 原点。
- 重要刻度。
- 当前研究区间。
- 有数学意义的参考点。

可以减少无关刻度与密集网格。

### 6.3 曲线

要求：

- 曲线平滑。
- 线条粗细一致。
- 当前研究对象最醒目。
- 背景参考曲线适当弱化。
- 没有不合理的裁切和变形。

### 6.4 关键点

对于 P、Q、A、B 等重要点：

- 清晰可见。
- 与曲线准确对应。
- 标签不遮挡其他数学信息。
- 在整个动画中保持身份一致。

对于经过变换的点，应优先称为“追踪点”或“对应点”。

例如峰点翻折后变成谷点时，不宜继续无条件称它为峰点。

### 6.5 坐标比例

在需要比较几何尺寸的同一坐标系内，应保持一致且明确的刻度。

尤其对：

- 伸缩。
- 旋转。
- 平移。
- 相似。
- 距离极值。
- 切线变化。

不得通过独立改变显示缩放比例制造虚假的数学关系。

## 7. 动画运动规范

### 7.1 数学运动优先

所有核心运动必须由数学模型驱动。

Manim 的 ValueTracker、Updater 或其他机制只能作为表现手段。

不能用人工设置的画面终点替代数学计算。

### 7.2 过渡风格

推荐：

- 平滑。
- 连续。
- 克制。
- 合理的缓入缓出。
- 必要的短暂停顿。

避免：

- 弹跳。
- 过度闪烁。
- 复杂旋转飞入。
- 无意义的缩放。
- 大范围的文字飞行动画。

### 7.3 时间节奏

建议：

| 动画环节 | 参考时长 |
|---|---|
| 建立数学场景 | 1～2 秒 |
| 单次主要数学运动 | 1～3 秒 |
| 关键临界状态 | 停留 0.7～1.5 秒 |
| 当前结论 | 停留 1～2 秒 |
| 文本切换 | 约 0.2～0.5 秒 |

具体时长取决于数学任务，不要求机械遵守。

### 7.4 数学临界状态

遇到以下内容应适当放慢：

- 相切。
- 极值点换位。
- 函数零点。
- 曲线重合。
- 不变量显现。
- 概率结果形成。
- 退化或边界状态。

**动画最值得停顿的位置，往往是数学关系真正发生变化的位置。**

## 8. 渐进式教学规范

每条 GIF 推荐遵循以下认知过程，但不强制固定分镜数量。

### A. 建立问题

学生看懂正在研究什么。

### B. 展示变化

让真正有数学意义的对象发生运动。

### C. 突出关键发现

通过高亮、停顿或对应关系让学生发现规律。

### D. 解释为什么

使用一个关键公式、一条辅助线或一句短解释。

### E. 总结结论

只保留最重要的结论。

这里的 E 不代表必须出现单独结尾页面。

简单数学 GIF 可以只包含三个阶段。

复杂内容如果需要较长解释，应考虑保留在 PDF 中，或拆分成多个独立动画。

## 9. 数学类型差异化

### 9.1 函数类

适合：

- 曲线变化。
- 参数变化。
- 对称。
- 单调性。
- 极值。
- 切线。
- 图像变换。

重点检查曲线、点与公式同步。

### 9.2 圆锥曲线类

适合：

- 动点轨迹。
- 切点与切线。
- 焦点性质。
- 距离变化。
- 极值。
- 几何不变量。

重点检查坐标、相切、相交及几何比例。

### 9.3 平面与立体几何类

适合：

- 构造。
- 折叠。
- 旋转。
- 投影。
- 截面。
- 辅助线变化。

重点避免透视效果造成数学误判。

### 9.4 概率统计类

适合：

- 随机实验过程。
- 样本组合。
- 频率趋近。
- 分布变化。
- 计数对应。

必须区分实验模拟结果与理论概率，避免用一次随机模拟冒充数学证明。

### 9.5 数列与代数类

适合：

- 项之间的递推关系。
- 数学归纳过程。
- 面积或数量累积。
- 公式逐步形成。
- 一一对应。

不强求连续几何运动。

**不同知识类型可以采用不同画面结构，但遵循相同视觉品质标准。**

## 10. GIF 技术规范

继续复用 Task 13F 冻结的生产工具。

推荐初始规格：

| 项目 | 推荐值 |
|---|---|
| 画布比例 | 9:16 |
| 分辨率 | 576×1024 |
| 帧率 | 12～15 FPS |
| 时长 | 视内容而定，通常 12～22 秒 |
| 循环 | 无限循环 |
| 文件大小 | 优先控制在约 2～6 MiB |
| 构建 | Manim → MP4 → FFmpeg → GIF |

以上是生产参考值，不是数学动画的硬性上限。

GIF 本身存在调色板限制，应尽量减少可能产生色带的复杂渐变和大面积透明叠加。

不能为了文件体积牺牲数学可读性。

## 11. 手机端适配规范

数学 GIF 最终是在知树 App 中阅读。

不能仅在 Windows 桌面大图上验收。

必须考虑：

- Android 实际显示宽度。
- 图片在详情页中的缩放方式。
- 不同屏幕密度。
- 页面安全区域。
- 字体实际可读性。
- 曲线实际线宽。
- 循环播放。
- 长时间观看的视觉舒适度。

每条 GIF 最终至少检查：

1. 标题能否清楚辨认。
2. 当前数学操作是否明显。
3. 关键点是否容易找到。
4. 关键公式是否清晰。
5. 图像是否被裁切。
6. 循环播放是否正常。

## 12. 禁止的视觉反模式

### 12.1 PPT 化

表现：

- 大量文字。
- 多个说明框。
- 每页都显示完整步骤。
- 数学图像被压缩。

处理：减少重复信息，突出图形与当前操作。

### 12.2 过度装饰

表现：

- 大量阴影。
- 高饱和渐变。
- 发光特效。
- 无意义图标。

处理：让数学关系本身形成视觉吸引力。

### 12.3 伪高级感

表现：

- 极淡的灰色文字。
- 过小的字体。
- 大量空白但图形很小。
- 模糊的玻璃背景。

处理：保证阅读效率，不用牺牲可读性换取“简约”。

### 12.4 数学失真

表现：

- 错误切点。
- 变换轨迹不准确。
- 数学对象比例错误。
- 曲线与公式不同步。

处理：回到数学模型验证，不能靠视觉调整掩盖错误。

### 12.5 模板化分镜

表现：

- 所有 GIF 使用相同的开场。
- 所有 GIF 强制采用同一三段卡片布局。
- 每条结论都必须有图像旋转或缩放。

处理：统一视觉设计语言，不统一数学教学过程。

## 13. 质量验收标准

每条 GIF 必须分别通过以下质量门。

### Gate M — Mathematics

- 数学模型正确。
- 公式与图形一致。
- 关键几何关系准确。
- 临界状态正确。
- 自动测试通过。

### Gate V — Visual Quality

- 数学图形突出。
- 信息层级清楚。
- 文字可读。
- 配色语义一致。
- 留白合理。
- 不存在不必要的装饰。

### Gate T — Teaching Value

- 具有明确教学目标。
- 动画比静态内容提供额外理解价值。
- 数学关键变化清楚。
- 不造成错误的数学暗示。

### Gate G — GIF Technology

- 可完整解码。
- 多帧真实运动。
- 无限循环正常。
- 没有异常黑帧或空帧。
- 真实关键帧与首尾正常。

### Gate D — Device

- Android 真机播放。
- 字体清晰。
- 图形清晰。
- 画面没有异常裁切。
- 循环正常。
- 用户明确确认真机效果。

数学 Gate 失败时，无论视觉多精美，都不能通过。

各 Gate 独立记录 PASS / FAIL / BLOCKED / PENDING 及验证证据。本地检查不能代替用户真机验收；用户未确认时，Gate D 保持 PENDING，不得标记 Android PASS 或动画 FINAL FREEZE。

### 13.1 视觉质量评分参考

以下 100 分量表只辅助 Gate V 的评审，不能代替数学正确性或用户验收。应依据真实关键帧和实际显示尺寸评分，并记录主要扣分原因。

| 维度 | 权重 |
|---|---:|
| 数学图形是视觉焦点 | 25 |
| 信息层级清楚 | 20 |
| 字体和公式可读 | 20 |
| 配色与辅助元素克制 | 15 |
| 动效自然、关键状态明显 | 10 |
| 品牌感与整体精致度 | 10 |
| 合计 | 100 |

- 85～100：达到推荐视觉品质。
- 75～84：针对问题继续优化。
- 低于 75：重新审查视觉设计。

数学 Gate 失败时，视觉分数再高也不能通过；达到 85 分也不代表 USER VISUAL PASS 或 ANDROID DEVICE PASS。

## 14. 与现有生产体系的关系

本视觉规范应作为所有新数学动画的共享设计约定。

## 15. 最终设计原则

**数学要准确。**

**图形要突出。**

**文字要克制。**

**颜色要有意义。**

**运动要解释数学。**

**留白要服务阅读。**

**每个画面只强调最重要的理解目标。**

**统一视觉语言，不复制数学分镜。**

最终目标：

**让学生不用努力寻找重点，就能看见数学关系如何发生、为什么成立，以及应该记住什么。**

这就是知树数学 GIF 应当追求的视觉品质。
