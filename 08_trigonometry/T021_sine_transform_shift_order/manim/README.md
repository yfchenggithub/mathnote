# T021 变换顺序动画

## 教学目标与数学约定

本动画回答：为什么先平移再横向伸缩所用的平移量是 `φ`，先横向伸缩再平移所用的平移量是 `φ/ω`，两条路径却到达同一图像？正式模型为 `y=A sin(ωx+φ)`，其中 `A≠0`、`ω>0`、`φ∈R`。`φ` 是有符号的向左平移量；`φ<0` 对应实际向右移动。振幅是 `|A|`，负 `A` 还须关于 x 轴翻折。动画不引入竖直偏移。

`math_model.py` 将基准点 `(t,sin t)` 映到 `(s t+h,c sin t)`。每条动态曲线都由同一状态反解得到 `y(x)=c sin((x-h)/s)`，金色点也由该状态计算，因而不会只让单个标记点重合。路径一终点 `(t-φ)/ω` 与路径二终点 `t/ω-φ/ω` 恒等。`S_ω L_φ=L_{φ/ω} S_ω` 中 `L_δ` 表示点的横坐标减 `δ`，`S_ω` 表示横坐标乘 `1/ω`；等式要求调整平移量，并不表示原操作可以直接交换。

演示取 `ω=2, φ=π/2, A=-2`，追踪同一个基准峰点 `t=π/2`。选用单一固定坐标系以保留手机画面中的刻度和曲线尺寸。蓝色为基准曲线，橙色为路径一，紫色为路径二，金色为峰点，绿色为共同结果。两路最终曲线按同一解析状态绘制，橙色宽底与紫色细线重叠；两个对应点同在 `(0,1)`，橙色环圈与金色点重叠。

## 分镜

| 时间（约） | 画面与可核对的点位 | 数学目的 |
| --- | --- | --- |
| 0–1 s | 蓝色 `sin x`，`P=(π/2,1)` | 两条实验从同一图像与同一点开始。 |
| 1–3 s | 橙色左移 `π/2`，`P:(π/2,1)→(0,1)` | 先平移 `φ`。 |
| 3–5 s | 橙色横坐标乘 `1/2`，P 留在 `(0,1)`，整条曲线压缩 | 路径一得到 `sin(2x+π/2)`。 |
| 5–8 s | 重新从蓝色基准出发，紫色先压缩，`P:(π/2,1)→(π/4,1)` | 展示路径二不同的中间曲线。 |
| 8–10 s | 紫色左移 `π/4`，`P→(0,1)` | 路径二得到相同水平结果。 |
| 10–12 s | 橙紫曲线及橙环金点精确重合，出现复合关系与“不能直接交换”提示 | 解释改变顺序时为何须调整平移量。 |
| 12–14 s | 共同曲线纵向乘 `|A|=2`，`P:(0,1)→(0,2)` | 振幅为非负长度 2。 |
| 14–16 s | 关于 x 轴翻折，`P→(0,-2)` | 得到 `A=-2` 的目标函数。中间经过 0 只是几何过渡，并非正式参数 `A=0`。 |
| 16–18.16 s | 总结 `y=-2sin(2x+π/2)`，随后回到基准图像 | 形成循环。 |

## 文件与本地构建

- `math_model.py`：独立点及曲线数学状态。
- `test_math_model.py`：参数矩阵、插值、非交换与负 A 回归。
- `scene.py`：Manim 分镜；不含独立硬编码的曲线终点。
- `TASK_14C_2_RESULT.md`：实际生产与验收记录。

在仓库根目录运行测试时，将本目录加入 `PYTHONPATH`，再以 `python -B -m unittest discover -s 08_trigonometry/T021_sine_transform_shift_order/manim -p test_*.py -v` 执行。渲染、导出与受保护的正式 GIF 写入，使用冻结的 `scripts/manim/render.ps1` 和 `scripts/manim/export_gif.ps1`，参数见 `scripts/manim/README.md`。本动画构建根目录为 `build/manim/T021/14C_2`。
